The problem

        
Agents are forgetful.
Your bugs are not.

      

      

        

          Most browser agents start from zero on every run. They rediscover the
          same checkout, retry the same flaky selector, and hand you a bug report
          you can't reproduce. The work never compounds.
        

        

          gremlin keeps a memory. What it learns on Monday is load-bearing on
          Tuesday — so coverage grows while effort per run falls.
        

        
    
          
  •  Rediscovering the same flows every run
    • 
          
  •  Screenshots with no steps, logs, or replay
    • 
          
  •  Selectors that shatter on every deploy
    • 
        

      

    


    
    

      

        
How it works

        
Charter in. Test suite out.

        

          Three loops, running at once. The agent explores, the recorder proves it,
          and the memory turns repetition into leverage.
        

      


      

        

          

            01
            
              
            
          

          
Charter

          
Describe the job, not the CSS. “Checkout with a saved card, a coupon, and a shipping estimate.” That's the entire spec.

          plain English
        


        

          

            02
            
              
            
          

          
Hunt

          
The agent drives a real browser, poking at edges: empty states, bad input, interrupted flows. Every finding ships with video, DOM, network, and exact repro steps.

          replayable evidence
        


        

          

            03
            
              
            
          

          
Learn

          
Wins become heuristics. Dead ends become negative checks. The next run starts from everything the last one figured out — and you approve what sticks.

          compounding memory
        

      

    


    
    

      

        
Under the hood

        
An agent with an actual memory.

      


      

        

          

            
          

          
Persistent heuristics

          

            Every verified finding is written as a named, versionable rule —
            checkout.coupons.negative — so it's inspectable in review,
            diffable in git, and portable across branches.
          

          

        


        

          

            
          

          
Evidence, not vibes

          
Video, trace, network log and a runnable repro attached to every bug. If it isn't replayable, it isn't filed.

        


        

          

            
          

          
Self-healing selectors

          
When the DOM shifts, gremlin re-anchors on intent and role instead of brittle class names. UI refactors stop breaking the suite.

        


        

          

            
          

          
CI native

          
One command, JUnit and JSON output, inline PR annotations. Runs against preview deploys, not just localhost.

        


        

          

            
          

          
Human in the loop

          
New heuristics land as proposals. Approve, edit, or reject them before they become policy on your default branch.

        


        

          

            
          

          
Model agnostic

          
Bring your own model and browser. gremlin owns the loop, the memory, and the evidence format — not your vendor.

        


        

          

            
          

          
Deterministic replays

          
Each finding replays step-for-step against the same build, so a passing fix is provable — not a lucky green run.

        


        

          

            
          

          
Charters as docs

          
Charters are plain Markdown in your repo — reviewable by PMs and engineers, and versioned alongside the code they cover.
